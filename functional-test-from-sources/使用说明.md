# 功能测试用例技能说明

根据需求文档、原型图及前后端代码设计人工可执行的功能测试用例，最终只交付一个 `功能测试用例.xlsx`。不默认调用接口、操作页面或执行业务测试；生成时执行结果为“未执行”。

不要求另行提供角色说明、测试账号、接口文档、接口日志或运行日志。资料没有明确说明的角色、规则、账号、数据库数据不能编造。

数据库 MCP 可给可不给：当前可用时只读参考相关结构、约束和必要样本；不可用也继续设计，不索要连接。“数据库验证”按用例断言填需要或不需要，连接缺失属于执行依赖，写入信息缺口。

## 工作过程

先从原始材料建立独立需求清单，再选用八种方法设计场景与正常/边界/异常用例，最后反查覆盖并校验。没有用例的需求仍保留，不能由已写用例反推需求清单。校验通过仅代表结构与引用正确，不代表业务已经测试通过。

六张工作表固定为：测试说明、测试方法覆盖、测试场景、详细测试用例、需求覆盖、信息缺口。

## 文件分工

| 路径 | 内容 |
|---|---|
| `SKILL.md` | 输入、流程、参考文件读取时机和交付边界 |
| `references/材料抽取.md` | 需求、原型、代码来源与差异提取 |
| `references/覆盖合同.md` | 独立需求清单、覆盖追踪与完成标准 |
| `references/测试方法.md` | 八种方法及具体设计规则 |
| `references/判定.md` | 适用性、合并、优先级和预期判断 |
| `references/用例格式.md` | 六表字段、编号、取值及对应关系 |
| `references/示例.md` | 与正式字段一致的六表示例 |
| `references/输出与脚本.md` | 必做校验、扫描限制和可选导出 |
| `scripts/` | 定位、导出、结构与引用校验，以及维护时的回归检查 |

前后端或输出路径未指定时读取 `config/projects.json`。交付前运行 `validate_testcases.py "<文件路径>" --generation`，处理错误后再交付；无法运行时明确说明，不宣称通过。
