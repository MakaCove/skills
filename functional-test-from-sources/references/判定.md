# 判定

本文件负责适用性、合并、优先级和完成判断，方法细节见“测试方法.md”。

## 适用性

有输入或业务类别考虑等价类；明确范围考虑边界值；多条件共同决定结果考虑判定表/因果图；生命周期考虑状态迁移；连续业务步骤考虑场景法；组合过多考虑正交或成对组合；有依据的风险考虑错误推测。无法判断不是“不适用”，应记录缺少的规则或分析范围。

功能范围内确有相应操作才设计新增、删除、撤销、分页等场景，不机械套用清单。

## 合并与新增

只有步骤、断言、失败判定和风险等价，且不会遮挡关键条件或丢失取值覆盖时才合并。结果、提示、状态、数据影响、触发入口不同，或同为拒绝但原因不同，分别设计。

出现未覆盖等价类、明确边界、可行判定规则、关键条件独立验证、状态迁移、场景分支或高风险检查点时，应补用例或明确记录缺口。不能单凭方法已有一条用例认定该方法已覆盖。

## 优先级

- P0：核心流程、权限、关键状态、金额或重要数据一致性。
- P1：重要异常、边界和主要业务限制。
- P2：一般功能、筛选、分页、空状态和常规提示。
- P3：低风险体验。

按业务影响判断，不让某一类正常用例自动全部成为 P0。P0/P1 的业务规则或场景集合核对适用的成功和拒绝结果，不要求每条用例同时验证互斥的结果。

## 预期与执行条件

优先依据明确需求和原型。代码只帮助确认入口、参数、数据准备和观察位置，不能自动充当正确预期。来源冲突或缺少规则时关联信息缺口；无法确定的预期写“待确认：具体规则”，不写模糊的“按实际结果判断”。

页面拦截与接口拒绝是不同入口。若页面无法输入超长值，就测试输入限制；资料支持独立接口验证时再设计超长参数请求，不能在同一条预期中任选一种结果。

是否需要查库取决于断言，是否具备 MCP 是执行条件。无页面的接口检查可将页面预期写“不适用：接口检查”，但必须有明确接口或数据预期。

## 完成条件

按独立清单反查需求、适用对象、关键分支和方法范围，说明未覆盖或待确认项，再运行结构与引用校验。只有相应断言都已有用例才能标“已覆盖”。缺口如实保留，不为了通过校验造用例或规则。

没有实际执行记录时，不能写测试通过、问题已复现或可以上线。校验未执行、校验未通过、设计有缺口分别说明，不混为业务执行结论。
