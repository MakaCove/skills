# 用例格式

## Excel 工作表

### 测试说明

包含测试范围、输入来源、数据库 MCP 是否可用、分析限制和资料缺口。

### 测试方法覆盖

| 设计方法 | 适用性 | 对应用例 | 说明 |
|---|---|---|---|

固定 8 行，顺序只能是：等价类、边界值、判定表、因果图、状态迁移、场景法、正交或成对组合、错误推测。适用性只能填写：`适用`、`不适用`、`适用但未覆盖`。`适用`必须写用例编号；`不适用`必须写原因；`适用但未覆盖`必须写缺少的场景。

## 用例编写要求

- ID 使用 `TC-001` 递增。
- 设计方法只能填写：等价类、边界值、判定表、因果图、状态迁移、场景法、正交或成对组合、错误推测。可以写成“等价类 + 场景法”。
- 类型只能填写：正常、边界、异常。
- 操作步骤必须可执行，一步只做一个主要动作。
- 预期结果必须可观察、可判断，不能写“系统正常”。
- 前置条件应说明需要准备的数据、数据状态、操作后观察位置以及是否依赖数据库 MCP。
- 角色只有在需求、原型或代码中明确出现时才填写；没有明确资料时写“未定义”。
- 当前代码行为不能自动作为正确预期。
- 生成时执行结果填“未执行”。有执行记录后可以改为通过或失败。
- 数据库验证只能填写：需要、不需要。不能空着。
- 关联需求必须包含 `R-n` 或 `AC-n`，不能空着。
- 需求覆盖只强制维护需求编号到用例编号；原型、前端、后端和数据库位置找到才填写，找不到的内容放入信息缺口。
- P0、P1 用例必须覆盖成功和拒绝或失败结果。
- 边界和异常用例与正常用例共用“详细测试用例”表和同一套 TC 编号，通过“类型”筛选。
- 不输出独立的 Markdown 用例、追踪矩阵、测试准备说明或执行记录文件。
