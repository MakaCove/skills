# 材料抽取

本参考用于把需求、原型和代码整理成测试设计依据。最终只输出 `功能测试用例.xlsx`。

## 来源和编号

按以下顺序阅读：需求文档、原型图或页面、前端代码、后端代码、数据库 MCP（如果用户提供）。后读到的代码用于补充实现条件，不能把当前代码行为自动当成正确预期。

为可验收内容编号：

- `R-1`：需求规则
- `AC-1`：验收条件
- `UI-1`：页面或控件状态
- `API-1`：接口或关键参数
- `BR-1`：会改变结果的代码分支
- `PERM-1`：明确出现的角色或数据权限
- `STATE-1`：状态及状态迁移
- `DATA-1`：数据变化或一致性要求

没有来源依据的编号不创建。

## 需求

逐段提取：

- 功能目标和成功条件
- 字段是否必填、默认值、长度和格式
- 数值、金额和时间边界
- 空值、不选、全部和不限的含义
- 明确出现的角色、权限和数据归属
- 状态可以如何变化
- 失败后的行为和用户可见提示
- 需求明确排除的范围

需求内部冲突时分别记录，不自行选一条作为正确结果。

## 原型

记录可观察内容：

- 页面标题、入口、按钮、链接和操作顺序
- 字段标签、占位符、必填状态和默认值
- 下拉、单选、复选和开关的可见选项
- 禁用、隐藏、只读、加载、空数据和错误状态
- 提示、确认框和错误文案
- 页面跳转、返回和刷新行为

看不清的内容可以用代码补充，但注明“取自页面代码”。颜色、间距和纯视觉偏好不生成测试用例，除非需求明确要求。

## 前端代码

从页面、组件和请求封装中记录：

- 页面入口和用户操作
- 表单校验和按钮状态
- 可见文字与实际提交值
- 空值、不选和清空时的请求参数
- 接口成功、失败和异常响应的页面处理
- 页面刷新、列表更新和跳转逻辑

步骤写用户能看见的文字，不把类名、方法名或 SQL 写进操作步骤。

## 后端代码

从接口、业务服务、查询、保存、状态处理和异常分支中记录：

- 参数和业务校验
- 明确出现的权限和数据归属判断
- 数据查询、写入、更新和删除
- 状态变化和重复操作限制
- 失败响应和页面应能观察到的结果
- 可影响测试数据的数据库约束

代码证据使用“相对路径:行号”。找不到行号时写“无直接代码证据”，不能编造路径。

## 数据库 MCP

数据库 MCP 可用时只读取测试设计所需的表结构、字段约束、关联关系和必要数据。不可用时继续生成用例；无法确认的数据库检查点写入 Excel 的“信息缺口”工作表。不要虚构表名、字段名、账号或查询结果。

## 差异记录

需求、原型和代码存在差异时，在“信息缺口”工作表记录：

| 编号 | 需求表现 | 原型表现 | 当前代码表现 | 影响用例 | 需要确认的预期 |
|---|---|---|---|---|---|

预期结果优先依据明确需求和原型；代码用于补充测试条件。不要生成独立的口径确认文件。
