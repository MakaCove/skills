# 输出与脚本

## 最终交付

最终只交付一个文件：`功能测试用例.xlsx`。输出目录使用用户指定的路径；未指定时读取 `config/projects.json`。

Excel 工作表固定为：

1. `测试说明`
2. `测试方法覆盖`
3. `测试场景`
4. `详细测试用例`
5. `需求覆盖`
6. `信息缺口`

临时 Markdown、接口扫描 JSON、校验日志和执行记录不得作为最终附件交付。边界、异常和失败用例不单独建表，统一放在“详细测试用例”并通过“类型”筛选。

## 内部脚本

脚本可以用于内部扫描、校验和导出，不能改变最终单文件交付规则：

```text
analyze_codebase.py       静态扫描前后端代码
validate_testcases.py     校验最终 Excel 的 6 张表和字段。生成时加 --generation，此时执行结果必须是未执行
md_testcases_to_excel.py  仅作兼容导出，不是默认输入流程
```

`build_execution_template.py` 不属于默认流程，不作为最终交付文件。没有数据库 MCP 时，不生成虚构的数据库结果；在“信息缺口”中写明需要数据库或接口验证。
