# functional-test-from-sources

## 目标与输入

只负责生成一份 `功能测试用例.xlsx`，不排查 Bug、评价代码质量或提出修复方案。生成时执行结果为“未执行”，静态扫描、数据库只读查询、文件校验都不代表已经执行业务测试。

输入为需求文档、原型图或页面截图、前端代码、后端代码；数据库 MCP 可给可不给。不要求用户另行提供角色说明、测试账号、接口文档或运行日志。接口和参数从代码提取，资料未说明的角色、账号、表名、数据和正确预期不得编造。

使用用户明确指定的项目路径和输出目录；未指定的路径才从 `config/projects.json` 读取。多项目时依据用户指定的项目或配置的默认项目选择，不混用项目；路径不存在则记录限制，不擅自换项目。记录本次实际读取的资料版本和代码路径，无法确认版本时如实写明。

## 执行流程与参考文件

按阶段读取下列文件并完成对应工作，不只根据正文列出的功能名称直接生成用例：

| 阶段 | 参考文件 | 必须完成的工作 |
|---|---|---|
| 抽取材料 | [材料抽取.md](references/材料抽取.md) | 阅读需求、原型及相关代码，记录规则、入口、条件、来源与冲突 |
| 建立范围 | [覆盖合同.md](references/覆盖合同.md) | 在生成用例前建立独立的需求与验收条件清单，列出适用页面、接口、分支、状态和数据对象 |
| 设计用例 | [测试方法.md](references/测试方法.md)、[判定.md](references/判定.md) | 判断八种方法的适用性，设计场景、具体数据、步骤与断言；反查清单中的漏项 |
| 写入 Excel | [用例格式.md](references/用例格式.md) | 按六张表及统一字段整理内容；需要写法示范时读 [示例.md](references/示例.md) |
| 交付检查 | [输出与脚本.md](references/输出与脚本.md) | 运行生成阶段校验、修正错误，再人工复核断言与覆盖范围 |

先从需求和原型确定应有行为，再阅读前端页面、请求封装和后端入口、业务服务、公共校验及必要的数据访问代码。扫描脚本只提供定位线索，不能代替阅读业务逻辑；扫描未找到不代表功能不存在。

需求清单不得从已生成用例反推。没有用例的需求也必须保留在“需求覆盖”中，标明未覆盖或待确认及原因。只有编号而没有对应断言，不算覆盖。

## 数据库 MCP

开始时查看当前是否有可用的数据库 MCP；这不是开工条件，也不向用户索要连接。

- 可用时只读与测试设计相关的结构、约束、关联和最少必要样本，不执行写入或变更，不查询无关数据。
- 不可用时继续；库中无法确认的内容记入“信息缺口”，不虚构查询结果。
- “数据库验证”表示用例是否需要查库，与当前是否连接分开判断。需要但未连接时仍填“需要”，写明执行依赖；能够通过页面或接口充分判断时可以填“不需要”。

## 设计边界

按实际功能覆盖核心正常流程，以及适用的必填、格式、长度、数值、空值、重复数据、非法数据、重复提交、刷新返回、增删改、状态切换、查询分页、明确权限和数据一致性。不存在的功能不强行生成用例。

只有资料或相关代码提供对应路径依据时，才设计接口失败、网络异常、超时、重试或异步失败用例；缺少依据的检查点记录为信息缺口，不自造返回码或超时时间。

八种方法统一使用：等价类、边界值、判定表、因果图、状态迁移、场景法、正交或成对组合、错误推测。适用才用；方法名称、适用性和覆盖关系按参考文件执行，不能仅贴方法标签而没有对应设计。

预期以明确需求和原型为依据，代码用于确认实际入口、参数和执行条件。来源冲突时分别记录各自表现；预期无法确定的用例写明待确认和关联缺口，不自行选当前代码作为正确答案。

## 用例与交付

每条用例写清具体输入、数据状态、可执行步骤和可观察的判定结果；不编造测试账号或现成单据。正常、边界、异常共用“详细测试用例”和从 `TC-001` 连续递增的编号。关联需求必须是清单内的 `R-n` 或 `AC-n`。

最终只交付 `功能测试用例.xlsx`，工作表顺序固定：

1. 测试说明
2. 测试方法覆盖
3. 测试场景
4. 详细测试用例
5. 需求覆盖
6. 信息缺口

交付前必须运行 `scripts/validate_testcases.py <文件路径> --generation` 并处理错误。校验通过只说明结构与引用符合规则；仍须按原始需求清单人工核对断言、边界和组合。依赖不可用导致校验未运行时必须如实说明，不能声称通过。资料不足以设计任何用例时说明限制，不能用空表冒充已完成。

不另交 Bug 报告、修复建议、Markdown 用例、扫描 JSON、执行记录或测试脚本；分析过程中可以使用临时材料，但不得作为额外附件。
