# Bug 排查技能说明

本技能只负责根据需求文档、原型图、前端代码和后端代码排查实现缺陷。用户把测试用例和需求、原型一起给出时，用例只作为额外检查清单，需求、原型和代码的排查仍然全做。这次没给用例时，按需求、原型和代码排查。

数据库不是必须输入。执行时如果当前已经连着数据库 MCP，就只读表结构、约束和必要样本作为参考；没连上就继续完成前后端代码审查，不向用户索要连接。依赖数据库才能确认的问题标记为“需要运行验证”。

不要求用户提供用户角色说明、测试账号、接口文档、接口日志或运行日志。接口和完整执行路径从前后端代码中追踪；资料没有明确说明的内容不自行编造。

最终只交付一个文件：`Bug排查报告.md`。

## 目录

| 路径 | 内容 |
|------|------|
| `SKILL.md` | 审查流程、证据要求、严重程度和输出约束 |
| `references/材料抽取.md` | 需求、原型和代码的抽取方法 |
| `references/生命周期核对.md` | 从入口到保存、执行和写回的检查方法 |
| `references/判定.md` | Bug、疑似问题和待确认问题的判定方式 |
| `references/核对合同.md` | 预期明确、路径可达、公共保护和因果证据的定性门槛 |
| `references/清单格式.md` | 报告结构和问题字段 |
| `references/输出.md` | 单文件交付规则 |
| `references/示例.md` | 静态确认、公共机制排除及未找到实现的写法 |

前端目录、后端目录或输出目录未指定时，读取 `config/projects.json`。用户指定项目优先，配置支持 OMS 和 WMS，默认 OMS；必须使用同一项目的前后端目录。配置或路径不可用时记录缺口，不切换到另一个项目。没有数据库 MCP 时，不重复要求用户提供。

执行阶段和参考读取顺序见 `SKILL.md`。当前方法里没有校验不代表整条链路没有校验；只有排除相关公共保护、确认入口可达且预期明确，才能静态确认 Bug。并发、事务、缓存等机制按实际代码存在情况检查，任务类规则不强加到普通页面功能。
