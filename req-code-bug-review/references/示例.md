# 示例

下面示例只说明如何从需求和代码推导问题，不代表任何具体项目。

## 资料

需求：已提交状态的数据不能被普通用户修改。

原型：已提交状态的编辑按钮不可用。

前端代码：页面根据状态隐藏编辑按钮。

后端代码：修改接口只校验数据编号，没有校验当前用户和数据归属，也没有校验数据状态。

## 审查结论

### 已确认问题

#### BUG-001 已提交数据可被接口直接修改

- 严重程度：P1
- 结论：已确认 Bug
- 证据状态：需求和代码均明确
- 运行状态：未实际运行
- 需求依据：已提交状态不能修改
- 原型依据：已提交状态编辑按钮不可用
- 代码位置：后端修改接口只校验数据编号
- 触发条件：调用修改接口并提交已提交数据的编号
- 预期行为：接口拒绝修改并返回无权限或状态错误
- 当前代码行为：接口只要编号存在就继续执行修改
- 影响范围：可构造接口请求的用户可能修改不应修改的数据
- 根因分析：修改接口没有判断数据状态，也没有判断这条数据是否属于当前用户
- 修复方向：在后端增加状态校验和数据归属校验
- 验证要求：运行接口并使用不同数据状态和数据归属验证

## 注意

如果只能从代码推测接口最终行为，必须写“代码路径确认”或“需要运行验证”，不能写成“已经复现”。如果需求没有明确普通用户和管理员的差异，应标记为需求不明确，不自行补充角色规则。
