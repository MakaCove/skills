## 1. 可以静态确认的状态校验遗漏

本例需求 R-1：普通用户只能修改草稿记录的标题，已提交记录禁止修改。本例原型 UI-1：已提交记录的编辑入口不可用。没有提供数据归属规则，因此不额外推导“用户只能改自己的记录”。

本例已读取的最小链路：

`web/record-editor.ts`（下方第 1～3 行）：

```typescript
function save(id: number, title: string) {
  return request.put(`/records/${id}`, { title });
}
```

`api/RecordController.java`（下方第 1～4 行）：

```java
@PutMapping("/records/{id}")
public void rename(@PathVariable long id, @RequestBody RenameRequest body) {
    recordService.rename(id, body.title());
}
```

`service/RecordService.java`（下方第 1～5 行）：

```java
public void rename(long id, String title) {
    Record record = repository.findById(id).orElseThrow();
    record.setTitle(title);
    repository.save(record);
}
```

本例同时约定已读到这些事实：当前普通用户具备该路由权限；请求校验只限制标题格式；公共拦截器只做登录和路由权限检查；没有其他状态校验切面或父类处理；仓储保存不检查记录状态，数据库没有阻止已提交记录改标题的约束。若这些事实实际没查到，就不能照本例确认 Bug。
