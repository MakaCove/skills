# 清单格式

```markdown
# Bug 排查报告

## 审查范围
- 需求文档：
- 原型图：
- 前端代码：
- 后端代码：
- 数据库 MCP：可用 / 未提供
- 审查限制：

## 审查覆盖

| 需求或审查项 | 页面 | 前端 | 后端 | 数据库 | 状态 | 依据或原因 |
|---|---|---|---|---|---|---|

状态只能填写：已检查、本功能没有这一层、材料缺失、需要运行验证。

## 未审查范围

| 范围 | 缺少的材料或条件 | 不能下的结论 |
|---|---|---|

## 总体结论
- 已确认 Bug：
- 高概率 Bug：
- 需要运行验证：
- 需求不明确：
- 当前未发现明显问题的模块：

## 已确认问题

### BUG-001 标题
- 严重程度：P0 / P1 / P2 / P3
- 结论：已确认 Bug
- 证据状态：需求和代码均明确 / 原型和代码明确 / 仅代码推导 / 仅数据库现象 / 需要运行验证
- 运行状态：未实际运行 / 已运行验证 / 部分运行验证
- 影响模块：
- 需求依据：
- 原型依据：
- 代码位置：
- 数据库依据：
- 触发条件：
- 推导或复现步骤：
- 预期行为：
- 当前代码行为：
- 影响范围：
- 根因分析：
- 修复方向：
- 验证要求：

同一根因的多个入口写在这一条下面，不另起编号。

## 高概率问题

### BUG-002 标题
- 结论：高概率 Bug
- 证据状态：
- 运行状态：未实际运行
- 其余字段与已确认问题相同

## 需要运行验证

### BUG-003 标题
- 结论：需要运行验证
- 证据状态：需要运行验证
- 运行状态：未实际运行
- 验证依赖：数据库待确认
- 其余字段与已确认问题相同

没有数据库连接、又必须看库才能确认时，结论写“需要运行验证”，验证依赖写“数据库待确认”。

## 需求或原型不明确项

### BUG-004 标题
- 结论：需求不明确
- 证据状态：
- 运行状态：未实际运行
- 不明确的内容：

## 数据库核查结果

未提供数据库连接时写“未提供，未核查”。提供时只写与本业务有关的只读结果。
```

没有实际运行时，运行状态写“未实际运行”，不把静态代码推导写成“已实际复现”。没有需求依据时，不把个人偏好或代码风格问题定性为 Bug。修复方向只写一句，不写补丁或 SQL。
