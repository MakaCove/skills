# 材料抽取

本参考用于把需求、原型和代码整理成 Bug 审查依据。最终只输出 `Bug排查报告.md`。

## 阅读顺序

依次读取需求文档、原型图或页面、前端代码、后端代码、数据库 MCP（如果用户提供）。后读到的代码用于确认当前实现路径，不能覆盖需求和原型中明确的预期。

不要求用户提供用户角色说明、测试账号、接口文档、接口日志或运行日志。缺少这些资料时，从代码中提取已经明确出现的条件；无法确认的内容标记为“需求不明确”或“需要运行验证”。

## 需求

逐条提取：

- 功能目标和成功条件
- 字段、格式、长度和边界
- 空值、不选、全部和不限的含义
- 明确出现的角色、权限和数据归属
- 状态和允许的状态迁移
- 失败后的页面、接口和数据结果
- 明确排除的范围

需求内部冲突时保留两种说法，不能自行选取一条作为正确预期。

## 原型

记录会改变结果的界面事实：

- 页面入口、按钮、链接和操作顺序
- 字段标签、默认值、必填、只读、禁用和隐藏
- 下拉或单选的可见选项
- 成功、失败、空数据、加载和确认状态
- 页面跳转、刷新和列表更新

颜色、间距和个人偏好不作为 Bug 依据，除非需求明确规定。

## 前端代码

沿页面入口追踪：

- 事件处理和请求参数
- 页面校验与按钮状态
- 可见文字和提交值的映射
- 空值、不选、清空时的参数
- 接口成功、失败和异常响应处理
- 保存后页面、列表和状态更新

记录相对路径和行号；找不到行号时写“代码位置待确认”，不要编造。

## 后端代码

沿接口入口追踪：

- 参数和业务校验
- 权限和数据归属判断
- 查询、保存、更新、删除和状态变化
- 异常、事务和返回结果
- 任务、消息或其他后续处理

必须解释从输入到结果的完整路径，不能只贴一个可疑代码片段。

## 数据库 MCP

提供数据库 MCP 时只做必要的只读核查：表结构、字段约束、唯一性、关联关系、状态值和必要数据。未提供时继续进行代码审查，不得虚构数据库结果；依赖数据库才能确认的问题标记为“需要运行验证”。

## 事实记录

先记录事实，再判断结论：

| 编号 | 需求或原型预期 | 代码路径 | 推导结果 | 证据位置 |
|---|---|---|---|---|

只有预期明确且代码路径确定地产生错误结果时，才进入 Bug 详情。
