# 材料抽取

本参考用于把需求、原型和代码整理成 Bug 审查依据。最终只输出 `Bug排查报告.md`。

## 阅读顺序

依次读取需求文档、原型图或页面、前端代码、后端代码、数据库 MCP（如果用户提供）。后读到的代码用于确认当前实现路径，不能覆盖需求和原型中明确的预期。

不要求用户提供用户角色说明、测试账号、接口文档、接口日志或运行日志。已有条件从实际材料提取；业务预期不清写“需求不明确”，模块或配置没提供写审查状态“材料缺失”，具体行为依赖运行证据时才写“需要运行验证”，三者不混用。

## 需求

逐条提取：

- 功能目标和成功条件
- 字段、格式、长度和边界
- 空值、不选、全部和不限的含义
- 明确出现的角色、权限和数据归属
- 状态和允许的状态迁移
- 失败后的页面、接口和数据结果
- 明确排除的范围

需求内部冲突时保留两种说法，不能自行选取一条作为正确预期。

用户已经明确补充的规则注明来源，只替代其明确修订的部分。原型缺少某个状态不证明代码必须没有该状态；用例预期错误也不代表需求本身不明确。

## 原型

记录会改变结果的界面事实：

- 页面入口、按钮、链接和操作顺序
- 字段标签、默认值、必填、只读、禁用和隐藏
- 下拉或单选的可见选项
- 成功、失败、空数据、加载和确认状态
- 页面跳转、刷新和列表更新

颜色、间距和个人偏好不作为 Bug 依据，除非需求明确规定。

## 前端代码

沿页面入口追踪：

- 事件处理和请求参数
- 页面校验与按钮状态
- 可见文字和提交值的映射
- 空值、不选、清空时的参数
- 接口成功、失败和异常响应处理
- 保存后页面、列表和状态更新

跟进实际引入的组件、请求封装、路由守卫和响应转换，避免只看页面方法就认定没有校验或错误处理。

记录相对路径和行号；找不到行号时写“代码位置待确认”，不要编造。

## 后端代码

沿接口入口追踪：

- 参数和业务校验
- 权限和数据归属判断
- 查询、保存、更新、删除和状态变化
- 异常、事务和返回结果
- 任务、消息或其他后续处理

继续检查实际调用的父类、公共服务、校验注解、切面、过滤器、权限与租户约束、映射及持久化策略。存在并发、事务、重试或缓存时，按 `生命周期核对.md` 对应小节核对实际保护范围和失败路径。部署配置或依赖源码没提供时记录缺口，不默认它们不存在。

必须解释从输入到结果的完整路径，不能只贴一个可疑代码片段。

## 数据库 MCP

提供数据库 MCP 时只做必要的只读核查：表结构、字段约束、唯一性、关联关系、状态值和必要数据。未提供时继续进行代码审查，不得虚构数据库结果；依赖数据库才能确认的问题标记为“需要运行验证”。

## 事实记录

先记录事实，再判断结论：

| 编号 | 需求或原型预期 | 代码路径 | 推导结果 | 证据位置 |
|---|---|---|---|---|

“已确认问题”只收预期明确且完整可达代码路径确定产生错误结果的条目。证据不足的候选按 `判定.md` 进入高概率或需要运行验证；纯材料缺失写未审查范围，不为了补齐报告制造问题。
