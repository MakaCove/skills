# 项目分析 — 工作流

## 分析范围

- **只扫入口层**：Controller / Route / 前端 router，不深入 Service
- **如实记录**：认证、字段名从代码读取；禁止默认 JWT、admin/123admin
- **标注局限**：`requestBody` 仅为初步字段名；完整契约由下游读 DTO 补全
- **预标注主流程候选**：`mainFlowCandidates` + `stateHints` + `pageEntryHints` + `navigationTree`

**必分析**：API 端点清单、前端路由、认证机制、模块分组、`chainHints`、状态机线索、主流程候选、**导航树结构（layout component）**
**不分析**：Service 内部、DB Schema

输出结构见 [02_输出规范.md](02_输出规范.md)；下游见 [04_下游衔接.md](04_下游衔接.md)。

### 步骤 1～3

- 技术栈与路径：读 `pom.xml` / `package.json` 等（**勿假设** backend/frontend 目录名）
- Glob 模式见 [03_多栈扫描指南.md](03_多栈扫描指南.md)
- 后端：method、path、参数概览、鉴权
- 前端：route、component、页面 summary（须打开组件）

### 步骤 3.5：提取导航树（navigationTree）

**从布局组件源码中提取完整的侧栏/导航栏菜单层级结构。** 这是后续生成 UI 用例中 `click_menu` 步骤的关键输入。

**定位布局组件**：

| 框架 | 典型文件路径 |
|------|-------------|
| Vue + Element Plus | `src/layout/`, `src/components/Sidebar.vue`, `src/components/Layout.vue` |
| Vue + Ant Design | `src/layouts/BasicLayout.vue` |
| React + Ant Design | `src/layouts/BasicLayout.tsx`, `src/components/SiderMenu/` |
| 自定义 | 打开 `frontend.baseUrl` 首页 → 查看侧栏 DOM → 定位对应组件文件 |

**提取内容**：

打开布局组件文件，读取模板，提取：

1. **菜单层级**：
   - 一级菜单（如 `el-menu-item`、`a-menu-item`）：label、route、icon
   - 父级菜单（如 `el-sub-menu`、`a-sub-menu`、`SubMenu`）：label、icon、是否可展开
   - 子菜单：嵌套在一级菜单内的路由入口

2. **路由绑定**：
   - 从菜单的 `@click` / `:to` / `router-link` 属性提取路由 path
   - 无路由的一级菜单（纯分组）：`route: null`，`expandable: true`

3. **每个叶子页面的功能入口**（`features[]`）：
   - 工具栏按钮（如"新建"，`trigger: "toolbar-button"`）
   - 行内操作（如"编辑""删除"，`trigger: "row-action"`）
   - 更多操作下拉（如"更多"→"导出"，`trigger: "menu-item"`）
   - 每个 feature 标注 `type` + `evidence`

**输出格式**：

```json
"navigationTree": [
  {
    "level": 1,
    "label": "仪表盘",
    "route": "/dashboard",
    "requiresAuth": true,
    "expandable": false,
    "children": []
  },
  {
    "level": 1,
    "label": "资产管理",
    "route": null,
    "expandable": true,
    "children": [
      {
        "level": 2,
        "label": "订单管理",
        "route": "/orders",
        "features": [
          { "label": "新建订单", "type": "create", "trigger": "toolbar-button" }
        ],
        "detail": { }
      }
    ]
  }
]
```

Schema 详见 [shared/03_项目分析结构.md](../shared/03_项目分析结构.md)。

**核验**：生成后用下面的方式自查：

- [ ] 每个前端路由都有对应的导航树节点
- [ ] 多层级菜单的父子关系与源码一致
- [ ] 每个叶子页面标注了 features 和 detail
- [ ] 所有 label 与源码文案一致，无猜测命名

### 步骤 7：stateHints

扫描 DTO/Entity 中的 `status`/`state`/`type` 枚举字段：
- 找出 Controller 中改变状态的端点（`/submit`、`/approve`、`/publish`）
- 记录状态流转路径：`DRAFT → SUBMITTED → APPROVED`
- 每个 transition 标注 `endpoint` 和 `evidence`

### 步骤 8：mainFlowCandidates

汇总前三步的线索，输出主流程候选：
- `chainHints.candidateChains` → `resource-lifecycle` 类型候选
- `stateHints[].transitions` → `state-transition` 类型候选
- `crossModuleRefs` → `cross-module` 类型候选
- 每条标注 `confidence`：`high`（双重验证）/ `medium`（仅源码）/ `low`（推测）

### 步骤 9：pageEntryHints（含逐页 DOM 拆解）

扫描前端页面，必须**打开每个页面组件文件**查看模板/DOM 结构，不能只看路由入口：

**基础信息**：
- 每个模块的菜单入口、路由路径
- 判断操作类型：`create` / `state-transition` / `delete` / `export` / `edit`
- 记录 `evidence`（组件文件名 + 行号）

**逐页 DOM 拆解**（`detail` 字段，每条 pageEntryHint 必填）：

对于每个页面，打开对应组件源码（`.vue` / `.tsx` / `.jsx`），提取以下信息：

1. **弹窗/抽屉（dialog/modal/drawer）**：
   - `type`：`dialog` / `drawer` / `inline-form`
   - `dialogTitle`：弹窗标题文本（从组件 template/JSX 中提取）
   - `fields[]`：表单字段清单，每项包含：
     - `label`：字段标签文本（表单 label 或 placeholder）
     - `selector`：定位线索（`placeholder=xxx` / `label=xxx` / `testid=xxx`）
     - `required`：是否必填（从校验规则或 `required` 属性推断）
     - `type`：`text` / `number` / `select` / `textarea` / `date` / `checkbox` / `radio` / `upload`
   - `buttons[]`：操作按钮，每项包含 `label` + `type`（`submit` / `cancel` / `reset`）

2. **列表/表格（table/list）**：
   - `columns[]`：表格列名列表（从 `<el-table-column label="xxx">` 或 `<th>` 提取）
   - `rowActions[]`：行内操作按钮文案（如「编辑」「删除」）
   - `toolbarActions[]`：表格上方工具栏按钮文案（如「新建」「批量删除」「导出」）
   - `pagination`：是否存在分页控件（`true` / `false`）
   - `filterFields[]`：筛选/搜索字段（如有）

3. **Tab 页签**（如有）：
   - `tabs[]`：页签标签文本列表

4. **特殊交互**（如有）：
   - 确认弹窗（操作前二次确认）、抽屉嵌套、步骤条等

**提取规范**：
- selector 优先级：`placeholder` > `label` > `testid` > `文本内容`
- 字段 label 必须从源码文本中提取，不得猜测
- 弹窗操作中字段定位使用 `dialog:弹窗标题|字段placeholder` 格式
