# 产物目录布局

## 技能包 vs 目标项目

| 位置 | 角色 |
|------|------|
| 技能包 `scripts/` | 模板源 — 提供基础执行器，随技能包版本更新 |
| 目标项目 `ai-tests/` | 部署目标 — `scripts/` 由各执行阶段步骤 0 按需首次复制；`test-artifacts/` 存放全部产物 |

部署规则：
- 执行 UI 测试时 → 部署 `run-ui-tests.mjs` + `validate-artifacts.mjs` + `ui-test.config.json`
- 执行 API 测试时 → 部署 `run-api-tests.mjs` + `validate-artifacts.mjs`
- 文件已存在则跳过，不覆盖，保护项目定制修改

## 技能包内布局

```text
ai-test-pipeline/
├── scripts/                      ← 模板源
└── test-artifacts/               ← 示例配置（仅 ui-test.config.json）
```

## 目标项目内布局（部署后）

```text
项目根目录/
└── ai-tests/
    ├── scripts/                  ← 由执行阶段步骤 0 按需首次复制
    │   ├── run-api-tests.mjs
    │   ├── run-ui-tests.mjs
    │   └── validate-artifacts.mjs
    └── test-artifacts/
        ├── latest
        ├── project-analysis-{ts}.json
        ├── ui-test.config.json   ← 由 UI 执行步骤 0 部署
        ├── api-cases/
        ├── ui-cases/
        ├── api-reports/
        └── ui-reports/
```

## 执行约定

- 在**被测项目根目录**执行（该目录下应有 `ai-tests/`）
- 默认读取 `./ai-tests/test-artifacts`（相对当前工作目录）
- 可通过 `--artifacts-dir` 覆盖
- PowerShell 链式命令用 `;`，不要用 `&&`：`cd D:\项目; node ai-tests/scripts/validate-artifacts.mjs --type api`
