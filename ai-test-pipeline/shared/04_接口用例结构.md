# 接口测试用例结构

> **schema**：`ai-test-pipeline/api-case/v2`

接口测试用例文件是一个 **JSON 数组**：第一个元素为**元信息**（含 `coverage.mainFlowInventory`），其余为**用例对象**。

## 单条用例字段速查

| 分组 | 字段 | 必填 | 说明 |
|------|------|------|------|
| **基本信息** | `id` | ✅ | `TC-API-{模块}-{编号}`，文件内唯一 |
| | `title` | ✅ | 中文简短描述 |
| | `module` | ✅ | 小写英文模块名 |
| | `priority` | ✅ | P0/P1/P2/P3 |
| **追溯链路** | `trace.flowRefs` | ✅ | 主流程 id 数组（`FLOW-*`） |
| | `trace.dependsOn` | 条件 | 上游用例 id 数组 |
| | `trace.produces` | 条件 | 本用例产出的变量名 |
| | `trace.consumes` | 条件 | 本用例消费的变量名 |
| **请求** | `request.method` | ✅ | HTTP 方法 |
| | `request.path` | ✅ | 请求路径（支持 `{{var}}`） |
| | `request.headers` | 条件 | 请求头 |
| | `request.body` | 条件 | 请求体 |
| **断言** | `assertions` | ✅ | 断言列表（见 `断言语法.md`） |
| **提取** | `extract` | 条件 | `{ "变量名": "响应路径" }` |
| **Mock** | `mockData` | 否 | 用例级 mock，补缺失变量 |

---

## 文件结构

```json
[
  {
    "schema": "ai-test-pipeline/api-case/v2",
    "generatedAt": "2026-05-29T10:00:00+08:00",
    "sourceAnalysis": "ai-tests/test-artifacts/project-analysis-20260529-095500.json",
    "totalCases": 3,
    "mockData": { "customerId": "MOCK-CUST-001" },
    "coverage": {
      "mainFlowTotal": 2,
      "mainFlowsCovered": 2,
      "mainFlowCoveragePercent": 100,
      "uncoveredMainFlows": [],
      "orphanCases": 0,
      "mainFlowInventory": []
    }
  },
  { "id": "TC-API-ORDERS-001", "trace": { "flowRefs": ["FLOW-ORDERS-001"] }, "..." : "..." }
]
```

## 元信息（首元素）

| 字段 | 必填 | 说明 |
|------|------|------|
| `schema` | ✅ | 固定 `ai-test-pipeline/api-case/v2` |
| `generatedAt` | ✅ | ISO 8601 时间 |
| `sourceAnalysis` | 推荐 | 引用的 project-analysis 文件路径 |
| `totalCases` | ✅ | 实际用例数（**结果值，非 KPI**） |
| `mockData` | 推荐 | 全局 mock fixtures，执行器注入变量池 |
| `coverage` | ✅ | 覆盖统计与主流程清单 |

### coverage 字段

| 字段 | 说明 |
|------|------|
| `mainFlowTotal` / `mainFlowsCovered` / `mainFlowCoveragePercent` | **业务主流程**覆盖率，验收 **100%** |
| `uncoveredMainFlows` | 未覆盖主流程 id，应为 `[]` |
| `mainFlowInventory` | 主流程清单（见下文） |
| `orphanCases` | 无 `trace.flowRefs` 的用例数，应为 **0** |
| `flowChains` | 可选：链路覆盖统计 |

## mainFlowInventory[]（主流程清单）

```json
{
  "id": "FLOW-ORDERS-001",
  "name": "创建并提交订单",
  "module": "orders",
  "priority": "P0",
  "businessGoal": "用户创建订单并提交审核",
  "endpointSequence": ["POST /api/v1/orders", "PUT /api/v1/orders/{id}/submit"],
  "evidence": ["OrderController.create", "OrderController.submit"],
  "suggestedCaseIds": ["TC-API-ORDERS-001", "TC-API-ORDERS-002"],
  "chainVars": ["token", "orderId"],
  "mockHints": ["customerId ← mockData.customerId"],
  "confidence": "high"
}
```

用例通过 `trace.flowRefs: ["FLOW-ORDERS-001"]` 追溯。

## mockData（元信息 / 用例级）

**元信息级**：执行器启动时注入变量池。  
**用例级**：当次请求前补全缺失变量，不覆盖已有 extract 产出。

## 用例对象

```json
{
  "id": "TC-API-ORDERS-001",
  "title": "创建订单",
  "module": "orders",
  "priority": "P0",
  "trace": {
    "flowRefs": ["FLOW-ORDERS-001"],
    "dependsOn": ["TC-API-AUTH-001"],
    "produces": ["orderId"],
    "consumes": ["token"]
  },
  "request": {
    "method": "POST",
    "path": "/api/v1/orders",
    "headers": { "Authorization": "Bearer {{token}}", "Content-Type": "application/json" },
    "body": { "customerId": "{{customerId}}", "sku": "{{productSku}}" }
  },
  "assertions": [
    { "field": "status", "operator": "eq", "expected": 200 },
    { "field": "body.code", "operator": "eq", "expected": 0 },
    { "field": "body.data.id", "operator": "exists" }
  ],
  "extract": { "orderId": "body.data.id" }
}
```

## ID 命名（统一规则）

| 类型 | 格式 | 示例 |
|------|------|------|
| 主流程 | `FLOW-{MODULE}-{序号}` | `FLOW-ORDERS-001` |
| 用例 | `TC-API-{MODULE}-{序号}` | `TC-API-ORDERS-001`、`TC-API-AUTH-001` |

## 变量替换

在 `path`、`headers`、`body` 中使用 `{{变量名}}` 引用变量池中的值。

## 验收要点

- [ ] 每条主流程的 `suggestedCaseIds` 均有对应用例
- [ ] `orphanCases === 0`
- [ ] 所有 `trace.flowRefs` 可在 `mainFlowInventory` 中找到
- [ ] 所有 `trace.dependsOn` 引用存在
- [ ] 不以 `totalCases` 与端点数比较论「达标/未达标」
