# 工作流（API 用例生成）

1. 读取 `project-analysis`
2. 识别并确认 API 主流程
3. 生成 `mainFlowInventory`
4. 生成 API 用例 JSON，写入 `ai-tests/test-artifacts/api-cases/`
5. **生成完成后，向用户确认是否校验**（见下方「校验确认」）
6. 用户选择「执行校验」时，运行校验并反馈结果；选择「跳过」时不执行

输出目录：`ai-tests/test-artifacts/api-cases/`

Schema 见 [shared/04_接口用例结构.md](../shared/04_接口用例结构.md)。

## 步骤 3：API 断言规则（字段级深度校验）

> **目标**：每条 API 用例必须同时包含基础校验 + 按用例类型的字段级业务校验。
> **禁止**：所有用例只用 `status eq 200` + `code eq 0` + `exists` 三条断言。

### 3.1 基础断言（每条用例必含）

| 校验目标 | 断言 | 说明 |
|---------|------|------|
| HTTP 状态 | `{ "field":"status", "operator":"eq", "expected":200 }` | 请求本身成功 |
| 业务码 | `{ "field":"body.code", "operator":"eq", "expected":0 }` | 业务层未报错（若项目无 code 字段则跳过） |
| 关键字段存在 | `{ "field":"body.data.{字段}", "operator":"exists" }` | 核心返回字段非空（如 `body.data.id`） |

### 3.2 字段级断言（按用例类型追加）

生成 API 用例时，**不可只写基础断言**，必须根据 `request.body` 和 `project-analysis` 提取以下深度校验：

**字段来源**：
1. 从 `project-analysis.modules[].endpoints[].requestBody` 读取该端点的请求参数字段列表
2. 从 `project-analysis.modules[].endpoints[].responseBody` 读取该端点的响应字段列表
3. 从 `project-analysis.stateHints` 读取该资源的可能状态枚举值

| 用例类型 | 操作 | 必追断言 |
|----------|------|----------|
| **登录/注册** | POST 登录 | `body.data.token` **regex** JWT 格式；`body.data.expiresIn` **gt** 0；**exists** 除 token 外的其他必要字段 |
| **创建** | POST | 对 `request.body` 中的每个核心字段（非 mock 补全字段），追加 `body.data.{字段名}` **eq** `{{该字段请求值}}`；若资源有状态字段，追加 `body.data.status` **eq** 初始状态（从 stateHints 取第一个 state） |
| **列表查询** | GET list | `body.data.total` **gt** 0；`body.data.list` **type** `array`；`body.data.list[0].id` **exists**；若带筛选参数，首条关键字段 **eq** 筛选值 |
| **详情** | GET/:id | `body.data.id` **eq** `{{resourceId}}`；核心字段均为 **exists** |
| **编辑** | PUT/PATCH | 对每个被修改的字段 `body.data.{字段}` **eq** 更新后的值；核心字段 **exists** |
| **状态流转** | PUT 状态 | `body.data.status` **eq** 目标状态（从 stateHints.transitions 中取 `to`）；`body.data.updatedAt` **exists** |
| **删除** | DELETE | `body.data.id` **eq** `{{resourceId}}`；或 `body.code` **eq** 0 |
| **异常/守卫** | 未登录/无权限 | `status` **neq** 200；**exists** 错误信息字段 |

### 3.3 断言数量下限

| 用例类型 | 最少断言数 |
|----------|-----------|
| 登录 | 4 |
| 创建 | 4（含每个必传字段的 eq） |
| 列表查询 | 4 |
| 编辑 | 3 |
| 状态流转 | 3 |
| 删除 | 2 |
| 异常 | 2 |

**不满足则视为未完成，不可写入产物。**

### 3.4 字段级校验示例

```json
// 创建订单 — 完整断言
"assertions": [
  { "field": "status", "operator": "eq", "expected": 200 },
  { "field": "body.code", "operator": "eq", "expected": 0 },
  { "field": "body.data.id", "operator": "exists" },
  { "field": "body.data.customerId", "operator": "eq", "expected": "{{customerId}}" },
  { "field": "body.data.sku", "operator": "eq", "expected": "{{productSku}}" }
]

// 列表查询 — 完整断言
"assertions": [
  { "field": "status", "operator": "eq", "expected": 200 },
  { "field": "body.code", "operator": "eq", "expected": 0 },
  { "field": "body.data.total", "operator": "gt", "expected": 0 },
  { "field": "body.data.list", "operator": "type", "expected": "array" },
  { "field": "body.data.list.0.id", "operator": "exists" }
]

// 状态流转 — 完整断言
"assertions": [
  { "field": "status", "operator": "eq", "expected": 200 },
  { "field": "body.code", "operator": "eq", "expected": 0 },
  { "field": "body.data.status", "operator": "eq", "expected": "SUBMITTED" },
  { "field": "body.data.updatedAt", "operator": "exists" }
]
```

## 校验确认（生成后必做）

用例 JSON 写入完成后，**不要自动执行校验**。先用如下话术询问用户：

```text
API 用例已生成：<文件路径>

是否现在运行校验？
- 执行校验：我将运行 `node ai-tests/scripts/validate-artifacts.mjs --type api`
- 跳过校验：暂不校验，你可稍后手动执行；执行用例前仍建议先校验

请回复「执行校验」或「跳过校验」。
```

| 用户回复 | Agent 行为 |
|----------|------------|
| 执行校验 / 需要 / 是 | 运行 `node ai-tests/scripts/validate-artifacts.mjs --type api`，输出通过或失败明细 |
| 跳过校验 / 不需要 / 否 | 不运行校验；提醒「执行测试前建议先校验：`node ai-tests/scripts/validate-artifacts.mjs --type api`」 |
| 未明确回复 | 再次简短询问，不擅自执行或跳过 |
