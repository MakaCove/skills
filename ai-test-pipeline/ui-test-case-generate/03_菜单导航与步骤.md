# 菜单导航与步骤

> **用例步骤必须模拟真实用户操作路径，而不是地址栏直切路由。**  
> 本规则适用于任意 Web 项目与任意业务域，不绑定具体菜单文案、模块名或框架实现。

---

## 1. 核心原则

| 维度 | 正确做法 | 错误做法 |
|------|----------|----------|
| 进入业务页面 | 菜单/导航入口点击 → 等待页面加载 → 再操作功能 | 用 `navigate` 直接打开业务路由 |
| 多层级菜单 | **只需一步 `click_menu` 到叶子页面**。执行器通过 `routeMenuMap.menuGroup` 自动展开父级菜单，用例层不必逐级点父级 | 对父级菜单也写 `click_menu`（父级无 `.last-menu-item` 叶子项，执行器会轮询所有一级菜单并失败） |
| 认证页操作 | 先进入认证页，再切换模式（如登录/注册）并提交 | 假定已在目标模式，直接点击同名按钮 |
| 多分区页面 | 先切 Tab/分段，再执行表单或表格操作 | 默认当前分区正确，跳过切换步骤 |
| 需会话页面 | 先建立/确认会话，再通过菜单进入业务页 | 每条用例重复登录；或无会话直接测业务功能 |
| 操作文案一致性 | 所有 `target`（菜单、按钮、字段 label/placeholder、弹窗标题、Tab 名、列名）必须取自组件源码，**逐字一致**（含空格和标点）。源码是"新增品牌"则不可写"新建品牌" | 凭经验猜测 target 文案，与源码不一致导致执行器定位不到元素而失败 |
| 步骤顺序强制 | 步骤必须按真实用户操作顺序排列：建立会话 → 进入页面(wait) → 打开功能入口(wait) → 填写表单(wait) → 提交(wait) → 断言。**不可跳过中间步骤或打乱顺序** | 还没 click("新建") 就直接 fill；断言在 wait 之前；缺少 wait 导致 DOM 未就绪 |

`navigationModel` 统一使用 `menu-driven`。

## 2. 完整 action 表（共 26 个）

### 2.1 会话 / 环境

| action | 目标 | 说明 |
|--------|------|------|
| `reset_session` | — | 清除 cookie/localStorage/sessionStorage，跳转登录页 |
| `ensure_session` | — | 若未登录则自动登录；已登录只关闭残留弹窗/菜单，不改变路由 |
| `open_login` | — | 打开认证页面（内部用 navigate） |
| `reset_page` | — | 关闭所有非固定标签页 → 导航到首页 → 关闭残留弹窗。仅用于需要完全重置 DOM 的高级场景 |
| `dismiss_menu` | — | 关闭已展开的菜单/弹窗/遮罩层，通常无需手动写；执行器会在用例结束时自动调用 |

### 2.2 导航

| action | target 约束 | 说明 |
|--------|-------------|------|
| `click_menu` | `routeMenuMap` 中存在的叶子页面 `menuLabel`（**不可用父级分组名**） | 通过侧栏菜单进入业务页面。执行器自动展开父级菜单 |
| `switch_auth_tab` | 认证模式页面 Tab 文案 | 切换登录/注册等模式 |
| `switch_tab` | 页面内 Tab 文案 | 多分区详情页/设置页切换 |
| `activate_tab` | 多标签页标题文案 | 在被测项目的多标签页栏中激活指定标签 |
| `navigate` | 页面 URL 路径 | **仅用于路由守卫测试、深链专项、或认证页入口。业务页面禁止使用** |

### 2.3 交互

| action | target 约束 | 说明 |
|--------|-------------|------|
| `click` | 按钮/链接/行/卡片/面包屑/入口文案 | 鼠标左键点击 |
| `double_click` | 同上 | 鼠标左键双击 |
| `right_click` | 同上 | 鼠标右键点击 |
| `fill` | 输入框 placeholder 或 label 文案 | 表单文本/数字输入 |
| `clear` | 输入框 placeholder 或 label 文案 | 清空已填写内容 |
| `select` | 输入框 target，value 可选 `first`/`last`/具体 option 文案 | 选择下拉选项（Element Plus / Ant Design / 原生 select 通用） |
| `select_dropdown` | 下拉触发元素（如 Select 组件占位文案） | 点击触发下拉展开后搜索并选择 option |
| `check` | checkbox/radio 文案或标签 | 勾选复选框/单选框 |
| `uncheck` | checkbox 文案或标签 | 取消勾选 |
| `upload_file` | 上传触发区域文案（如"点击上传"），value 为绝对路径或相对项目根的路径 | 文件上传 |
| `hover` | 元素文案 | 鼠标悬停 |
| `wait` | value 为毫秒数（字符串/数字） | 等固定时长 |

### 2.4 等待 / 调试

| action | target 约束 | 说明 |
|--------|-------------|------|
| `wait_visible` | 元素文案 | 等待指定元素出现在 DOM 中（最多 30s） |
| `press_key` | value 为按键名（如 `Enter`/`Escape`/`Tab`） | 模拟键盘按键 |
| `scroll` | value 为像素数 | 滚动页面 |
| `screenshot` | value 为可选文件名 | 截图保存到产物目录的 screenshots/ 下 |

### 2.5 步骤编排强制规则

每条用例的 `steps` 必须严格遵循真实用户操作时序：

1. **会话先行**：业务用例第一步固定为 `ensure_session`，认证用例第一步固定为 `reset_session`
2. **导航居中**：`click_menu` 仅用于从当前位置导航到目标页面，不用于"刷新"已打开的页面
3. **操作前必须打开入口**：填写表单前必须先 click 打开弹窗/侧栏/编辑页面；编辑前必须先通过列表页面进入
4. **wait 不可省略**：每两次页面级交互之间必须有 `wait`（click_menu 后、按钮触发弹窗后、表单提交后）
5. **断言在最后**：所有 assertions 在步骤全部执行完毕后才验证，不可在步骤中间混入断言

**自检方法**：按 `step` 序号逐条读，能否用鼠标在真实浏览器中复现？不能则步骤顺序错误。

## 3. `navigate` 使用边界

`navigate` 不是业务功能入口手段，仅用于以下场景：

1. 路由守卫专项（未登录访问受保护路由）
2. 深链/外链专项（需求明确要求）
3. `open_login` 的执行器内部实现（用例层仍写 `open_login`）

其余业务用例（可通过菜单到达）必须用 `click_menu`。

## 4. 路由—菜单映射（生成前必做）

在元信息写入 `coverage.routeMenuMap`，示例：

```json
"routeMenuMap": [
  { "route": "/module-a", "menuLabel": "模块A", "menuGroup": "业务域1", "requiresAuth": true },
  { "route": "/module-b", "menuLabel": "模块B", "menuGroup": "业务域2", "requiresAuth": true },
  { "route": "/brand", "menuLabel": "品牌信息", "menuGroup": "货品", "requiresAuth": true },
  { "route": "/owner", "menuLabel": "货主信息", "menuGroup": "基础", "requiresAuth": true },
  { "route": "/login", "menuLabel": null, "navigation": { "type": "direct" }, "requiresAuth": false }
]
```

要求：
- `menuLabel` 必须来自布局/侧栏源码中的**叶子页面文案**，而非一级菜单分组名。
- `menuGroup` 为叶子页面的父级菜单分组名，用于执行器自动展开父级菜单。
- 无菜单页面（如认证页）可用 `menuLabel: null`。

## 5. 通用步骤模板

### 5.1 认证主路径

```json
"steps": [
  { "step": 1, "action": "reset_session" },
  { "step": 2, "action": "open_login" },
  { "step": 3, "action": "fill", "target": "<用户名字段文案>", "value": "{{username}}" },
  { "step": 4, "action": "fill", "target": "<密码字段文案>", "value": "{{password}}" },
  { "step": 5, "action": "click", "target": "<登录按钮文案>" }
]
```

### 5.2 认证模式切换（如注册）

```json
"steps": [
  { "step": 1, "action": "open_login" },
  { "step": 2, "action": "switch_auth_tab", "target": "<目标模式文案>" },
  { "step": 3, "action": "fill", "target": "<字段文案>", "value": "<值>" },
  { "step": 4, "action": "click", "target": "<提交按钮文案>" }
]
```

### 5.3 业务模块单功能

**只需一步 `click_menu` 到叶子页面**。示例如：`routeMenuMap` 中有 `{ menuLabel: "品牌信息", menuGroup: "货品" }`。

```json
"steps": [
  { "step": 1, "action": "ensure_session" },
  { "step": 2, "action": "click_menu", "target": "品牌信息" },
  { "step": 3, "action": "wait", "value": "1000" },
  { "step": 4, "action": "click", "target": "<功能入口文案>" },
  { "step": 5, "action": "fill", "target": "<字段文案>", "value": "<值>" },
  { "step": 6, "action": "click", "target": "<确认文案>" }
]
```

### 5.4 跨模块流程

每个模块只需一步 `click_menu` 到叶子页面，无需写父级菜单步骤。

```json
"steps": [
  { "step": 1, "action": "ensure_session" },
  { "step": 2, "action": "click_menu", "target": "<模块A叶子页面文案>" },
  { "step": 3, "action": "..." },
  { "step": 4, "action": "click_menu", "target": "<模块B叶子页面文案>" },
  { "step": 5, "action": "..." }
]
```

## 6. `routeMenuMap` 与 `click_menu` 的关系

用例只写叶子页面的 `click_menu`，执行器通过 `routeMenuMap` 完成父级菜单展开：

```
用例步骤:                  click_menu("品牌信息")
                                ↓
routeMenuMap 查找:        { menuLabel: "品牌信息", menuGroup: "货品", route: "/brand" }
                                ↓
执行器 clickSubMenu:      hover("货品") → click(.last-menu-item[title="品牌信息"]) → waitRoute("/brand")
```

因此：
- **`menuLabel` 必须是叶子页面的文案**，不能是父级分组名（如"货品""基础""库内"）
- **`menuGroup` 是父级分组名**，执行器用它来自动 hover 对应的一级菜单
- **用例步骤只需一条 `click_menu`**，target 指向 `menuLabel`

## 7. 验收清单

- [ ] `navigationModel === "menu-driven"`
- [ ] `coverage.routeMenuMap` 已生成，且 `menuLabel` 为叶子页面文案，`menuGroup` 为父级分组名
- [ ] 业务用例中，菜单可达页面不使用 `navigate`
- [ ] **每条 `click_menu` 的 target 均为 `routeMenuMap` 中存在的 `menuLabel`，而非父级分组名**
- [ ] **不存在多余的父级 `click_menu` 步骤（如 `click_menu("货品")` 然后 `click_menu("品牌信息")`，应只有后者）**
- [ ] 认证模式切换类用例使用 `switch_auth_tab` / `switch_tab`
- [ ] 需会话业务用例使用 `ensure_session` 或显式上游依赖
- [ ] 弹窗内的字段 target 使用 `dialog:弹窗标题|定位线索` 格式
- [ ] 创建类用例覆盖了所有必填字段的填写（不可只填一个字段）
- [ ] 每条主流程至少包含：正向创建 + 必填校验 + 列表可见

## 8. 反模式

1. 全量业务用例都从 `navigate` 直达路由。
2. 菜单文案未核对源码，凭经验命名。
3. 认证模式切换仅 `click` 同名按钮，未切换 Tab/模式。
4. 负向认证用例未清会话，受到上条用例污染。
5. 跨模块流程用例未体现真实导航路径。
6. 创建类用例只填一个字段、其余字段跳过——必须覆盖表单中所有必填字段。
7. 断言只检查 URL，不验证数据正确性（如 toast 提示、具体字段值）。
8. **多级菜单生成了多步 `click_menu`（如 `click_menu("货品")` → `click_menu("品牌信息")`）。执行器只需要叶子页面一步，多余的父级步骤会导致轮询失败。**
9. **`routeMenuMap` 的 `menuLabel` 填入了一级分组名而非叶子页面文案。**
10. **步骤 `target` 值与源码文案不一致（源码是"确认"却写"提交"、源码是"新增品牌"却写"新建品牌"）——target 必须和源码逐字一致，包括空格和标点。**
11. **使用不在第 2 节 action 表中的未知 action 名或断言类型。**
