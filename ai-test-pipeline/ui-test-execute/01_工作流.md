# 工作流（UI 执行）

0. 确保执行脚本就绪 — 检查目标项目 `ai-tests/` 目录（见下方「步骤 0」）
1. 确认测试地址：用例 `meta.baseUrl` 或执行参数 `--base-url`（由用户提供，技能包不写死）
2. 运行校验：`node ai-tests/scripts/validate-artifacts.mjs --type ui`
3. 运行执行器：`node ai-tests/scripts/run-ui-tests.mjs`（或 `--base-url <地址>`）
4. 查看报告与截图：`ai-tests/test-artifacts/ui-reports/`

## 步骤 0：确保执行脚本就绪

执行 UI 测试前，先确保目标项目根目录下存在所需脚本和配置：

1. 定位目标项目根目录：`ai-tests/` 所在目录（通常即当前工作目录）
2. 若 `ai-tests/scripts/` 目录不存在，创建它
3. 检查并按需复制（文件已存在则跳过，保护项目定制修改）：
   - `ai-tests/scripts/validate-artifacts.mjs` ← 从技能包 `scripts/` 复制（校验脚本，UI/API 共用）
   - `ai-tests/scripts/run-ui-tests.mjs` ← 从技能包 `scripts/` 复制（UI 执行器）
   - `ai-tests/test-artifacts/ui-test.config.json` ← 从技能包 `test-artifacts/` 复制（浏览器配置）
4. 输出摘要：哪些已存在（跳过）、哪些刚复制

## 测试地址

- 来源优先级：`--base-url` > 用例 `meta.baseUrl`
- 无需事先确认服务是否启动；执行器直接访问给定地址，连不通则在用例/报告中体现失败
- 示例：`node ai-tests/scripts/run-ui-tests.mjs --base-url https://staging.example.com --limit 20`

## 关键点

- 默认**有头**模式（见 `ai-tests/test-artifacts/ui-test.config.json`），窗口**默认最大化**
- `click_menu` 优先使用 `routeMenuMap`
- 失败自动截图
