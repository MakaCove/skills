# 结论判定

负责将已有证据转为本版质量判断，不设置通用缺陷数量阈值、评分或发布准入建议。

## 先核对依据

明确目标版本、时间范围、业务影响、项目提供的验收/质量标准、关键验证和遗留项。没有标准时不编造合格阈值；可依据明确业务约束和实际影响判断，写明依据及限制。

“发布前少、发布后多”只是一种分布，可能受范围、使用量、观察期、收集方式等影响。可以列出待核对的验证缺口，不直接归因为测试不足。没有线上记录也不自动代表质量良好。

## 判断顺序

先判断有无充分证据支持确定性问题；证据缺失不能抹去已证实的业务失败。再看遗留风险，最后检查是否有依据支持可接受；无法支持任何等级时不评级。

| 结果 | 适用条件 |
|---|---|
| 质量不达标 | 已确认属于本版分析范围，且证据表明违反明确关键验收/质量标准、核心流程实际失败，或发生明确严重业务影响；写明具体标准或影响 |
| 有遗留风险 | 未发现足以支持不达标的事实，但有真实未关闭缺陷、已关闭而未消除的业务风险、明确尚未完成修复验证，或明确要求的关键检查已知未执行等具体风险 |
| 可接受 | 范围、观察期和关键证据足以支持判断；核心流程有明确通过依据，真实缺陷已闭环且修复验证有依据，没有未解释的待确认项、未关闭缺陷或与判断冲突的关键风险 |
| 暂不评级（证据不足） | 未能形成有依据的等级判断，例如版本归属、缺陷范围或核心验证未知；说明缺少什么、影响什么判断 |

前三项是质量等级；最后一项表示未作评级，不是第四个等级。仅有无实质影响的说明性缺口不必自动阻断评级，但必须说明为何不影响判断。存在已证实风险时可对已知范围写“有遗留风险”，同时说明其他范围仍无法判断。

同一材料既满足“有遗留风险”又有确定不达标证据时，结论为“质量不达标”，另列当前遗留项。仅待确认的缺陷不直接变成真实遗留缺陷；无法排除其关键影响时暂不评级。关键验证“未知”不等于“明确未执行”，不能混用。

## 发布质量与当前风险

分别说明初始发布表现和截至统计时点的遗留情况。观察期内的确定性严重失败不会因为后续已修好就从发布质量事实中消失；修复验证完成时，当前风险应据实更新。截止后的验证不能回填为截止前已通过。

同类问题再次出现、缺陷集中、数量较多，都不能单独触发“质量不达标”；结合对应标准、真实业务影响及验证证据判断。

## 结论写法

写清：质量等级或暂不评级、支持事实及来源、适用范围与限制、遗留项、下次优先补的验证范围或分析材料。不提供具体测试用例、修复代码或发布建议；不把“暂不评级”写成“可接受但材料不足”。
